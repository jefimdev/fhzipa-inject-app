================================================================================
GUIA DE EDICAO DO APLICATIVO - FHZIPA INJECT
================================================================================
Manual de referencia do codigo-fonte deste projeto.
Todos os caminhos sao relativos a raiz do repositorio (a pasta que contem
package.json, index.html, src/ e src-tauri/).

Ultima organizacao interna: pastas da interface reagrupadas por
responsabilidade, com nomes em portugues, minusculos e com hifen.
Nenhuma funcionalidade, texto, cor, layout ou URL publica foi alterada.

Este guia foi conferido contra os arquivos do projeto depois da
organizacao: todos os caminhos citados existem, todos os comandos citados
existem no package.json e todos os nomes de componente, variavel e chave
citados existem no codigo. Se voce mover ou renomear um arquivo, atualize
este guia junto.

Ultima atualizacao deste guia: a infraestrutura passou a usar npm de
forma consistente (instalacao local, GitHub Actions, scripts de CI,
scripts de versao e ambiente Nix), e o guia passou a explicar os
requisitos reais do Windows e o que cada pasta da raiz significa.

================================================================================
A. VISAO GERAL
================================================================================

O QUE E O APLICATIVO
--------------------
O FHZIPA INJECT e um aplicativo de DESKTOP (nao e um site) que instala
arquivos .ipa em iPhone e iPad conectados por USB no computador. Ele tambem
baixa .ipa de um catalogo integrado, pareia o aparelho, gerencia certificados
de desenvolvimento e App IDs da Apple e guarda as credenciais no chaveiro do
Windows.

Duas partes que trabalham juntas:
  * FRONTEND  -> a interface (React), dentro de src/
  * BACKEND   -> o codigo nativo em Rust (Tauri), dentro de src-tauri/

O frontend chama o backend por meio do comando `invoke(...)`
(@tauri-apps/api/core). Cada comando chamado no frontend tem um
correspondente em Rust registrado em src-tauri/src/lib.rs, na lista
`tauri::generate_handler![...]`. Se voce criar um comando novo, registre
nos dois lados.

TECNOLOGIAS
-----------
  Frontend
    React 19 + TypeScript (tsconfig "strict" ligado)
    Vite 8 (bundler + servidor de desenvolvimento)
    i18next / react-i18next (traducao, 28 idiomas)
    react-icons (todos os icones da interface sao de biblioteca, nao ha
                 arquivos de icone proprios no frontend)
    sonner (as mensagens/"toasts" do canto da tela)
    react-virtuoso (lista virtualizada dos registros de log)
    @tauri-apps/api, /plugin-dialog, /plugin-opener, /plugin-store
  Backend
    Rust estavel (toolchain x86_64-pc-windows-msvc)
    Tauri 2 (shell desktop, plugins dialog/opener/store)
    crates isideload e idevice (autenticacao Apple, assinatura, instalacao)
  Outros
    Nix (flake.nix / shell.nix / default.nix) - ambiente de desenvolvimento
    GitHub Actions (pasta .github/workflows) - build e publicacao
    npm como gerenciador de pacotes (package.json + package-lock.json)

QUAL PASTA ABRIR NO VISUAL STUDIO CODE
---------------------------------------
Abra a RAIZ do repositorio: a pasta que contem `package.json`.
Abrir uma pasta interna (por exemplo so `src/`) quebra o Vite, o TypeScript e
o Tauri, porque todos eles procuram a raiz para achar index.html, tsconfig.json
e src-tauri/.

A raiz contem:
    .github/      automacoes do GitHub
    .vscode/      recomendacoes de extensoes
    dist/         saida de build (gerada, nao editar)
    public/       arquivos servidos como estao (favicon)
    src/          todo o codigo da interface
    src-tauri/    todo o codigo nativo em Rust
    node_modules/ dependencias instaladas (gerada, nao editar)

ONDE FICA O PONTO DE ENTRADA
----------------------------
  Interface (web):  index.html  ->  src/main.tsx
                    O index.html carrega <script type="module"
                    src="/src/main.tsx">. O Vite precisa desse caminho
                    exato, por isso o arquivo main.tsx continua na raiz
                    de src/.

  Nativo (Rust):    src-tauri/src/main.rs  ->  src-tauri/src/lib.rs
                    A funcao `run()` de lib.rs monta o aplicativo Tauri,
                    registra os plugins e a lista de comandos.

COMO O APLICATIVO ESTA ORGANIZADO
----------------------------------

                        contexto e renderiza o componente principal

  componentes/          pecas de interface reutilizadas (uma por arquivo)
  paginas/              as telas do menu (uma por arquivo)

                        dispositivos/pareamento)
  contextos/            estado global compartilhado (React Context)

COMO INSTALAR O VISUAL STUDIO BUILD TOOLS (itens 4 e 5)
---------------------------------------------------------
  A Microsoft publica um instalador oficial que instala SO o que o
  projeto precisa, sem o Visual Studio completo:

    1. Baixe o instalador:
         https://aka.ms/vs/17/release/vs_BuildTools.exe

    2. Execute com estes componentes (ou o equivalente pela interface):
         --installPath "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools"
         --add Microsoft.VisualStudio.Workload.VCTools
         --includeRecommended

       Na interface, a opcao correspondente e "Desenvolvimento para
       Desktop com C++". O "--includeRecommended" traz o Windows SDK, o
       compilador MSVC (cl.exe) e o linker (link.exe) de 64 bits.

    3. Exige elevacao de administrador (o Windows pergunta). Depois de
       terminar, abra um terminal NOVO: o caminho das ferramentas so entra
       no PATH quando o terminal e reaberto.

  COMO CONFERIR QUE DEU CERTO (sem abrir o aplicativo):
      where link.exe
      where cl.exe
      rustc -vV          (o host deve ser x86_64-pc-windows-msvc)
      cargo check --manifest-path src-tauri\Cargo.toml
  Se "where link.exe" nao encontrar nada, o Build Tools nao esta instalado
  ou o terminal ainda nao foi reaberto.

  NAO E PRECISO COLO CAR NO PATH
  O Rust encontra o compilador e o linker do MSVC sozinho, pelo registro
  do Windows. Nao precisa de "Developer Command Prompt" nem de mexer no
  PATH. Para saber ONDE a ferramenta esta instalada:
      "C:\Program Files (x86)\Microsoft Visual Studio\Installer\vswhere.exe" ^
        -products * -format value -property installationPath
  O caminho padrao do Visual Studio Build Tools e
      C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools
  e o compilador/linker ficam em
      <instalacao>\VC\Tools\MSVC\<versao>\bin\Hostx64\x64\link.exe
  (o Windows SDK fica em "C:\Program Files (x86)\Windows Kits\10").

  ATENCAO - um "link.exe" do Git (em C:\Program Files\Git\usr\bin) NAO e o
  linker da Microsoft: e um utilitario Unix com o mesmo nome e nao serve
  para compilar Rust.

================================================================================
C. COMO EXECUTAR
================================================================================

ABRIR O TERMINAL
----------------
  No Visual Studio Code: menu Terminal > Novo Terminal (ou Ctrl+`).
  Ele abre na raiz do projeto. Se nao abrir, use o menu Terminal >
  Selecionar Pasta Inicial.

INICIAR O APLICATIVO DESKTOP (o que o usuario final usa)
---------------------------------------------------------
    npm run tauri dev

  O que acontece: o Vite sobe em http://localhost:1420, o Rust compila em
  modo debug e a janela do aplicativo abre. As alteracoes no frontend
  aparecem sozinhas (hot reload); alteracoes em src-tauri/src/*.rs fazem o
  Rust recompilar e a janela reabrir.

  Endereco: o aplicativo abre como JANELA PROPRIA do Windows, com o titulo
  "FHZIPA INJECT" (nao e uma aba de navegador). Tamanho inicial 1600x960,
  minimo 1024x700, definidos em src-tauri/tauri.conf.json.
  A URL http://localhost:1420 e usada DENTRO da janela do aplicativo; nao e
  um site para uso direto. O icone que aparece na barra de titulo e na
  barra de tarefas vem de src-tauri/icons/ (veja a secao E).

  Atencao: este comando precisa do Visual Studio Build Tools com C++ e do
  WebView2 Runtime. Se faltar, o erro aparece na etapa do Rust
  ("linker `link.exe` not found" ou similar). Na duvida, veja a secao K.

INICIAR SO A INTERFACE (para mexer no visual com mais rapididao)
---------------------------------------------------------------
    npm run dev

  O Vite serve a interface em http://localhost:1420. Voce pode abrir essa
  URL no Chrome/Edge, mas o aplicativo NAO vai funcionar no navegador
  comum: as chamadas ao backend Tauri (`invoke`) vao falhar com
  "Cannot read properties of undefined (reading 'invoke')" e a tela fica
  em branco. Serve para conferir folhas de estilo, textos e layout, e
  nada mais.

  DIFERENCA ENTRE OS DOIS MODOS (importante)
  -------------------------------------------
  `npm run dev`      -> SOMENTE a interface, servida pelo Vite. Roda em
                         qualquer navegador, mas sem o backend Rust: nada
                         de dispositivos, conta Apple, certificados, loja
                         ou logs funciona.
  `npm run tauri dev`-> O APLICATIVO DE VERDADE: janela do Windows, com
                         o backend Rust (Tauri) junto. E este modo que
                         serve para conferir o funcionamento.
  Para conferir a versao de producao (mesmo frontend que vai no
  instalador), veja a secao J.

  OUTRO MODO DE VERIFICAR (para quem nao tem o Build Tools instalado)
  --------------------------------------------------------------------
  Se o `npm run tauri dev` falhar por falta do linker, ainda da para ver
  o frontend DENTRO de uma janela nativa: compile a interface
  (`npm run build`) e sirva-a com `npm run preview`, abrindo
  http://localhost:4173 no navegador. A aparencia e os textos sao os
  mesmos do aplicativo, mas as integracoes com a Apple NAO funcionam
  (sao substituidas por respostas vazias). Serve para conferir layout,
  nao para conferir funcionalidade.

COMO ENCERRAR
-------------
  No terminal do VS Code: Ctrl+C.
  Se a janela do aplicativo continuar aberta, feche-a.
  Se o cargo travar, feche a janela do aplicativo e pressione Ctrl+C
  de novo.

QUANDO REINICIAR
----------------
  Alteracao em src/**  ->  nao precisa reiniciar nada; o Vite recarrega
                           sozinho (hot reload). Se a tela ficar
                           inconsistente, recarregue (Ctrl+R na janela
                           do aplicativo).
  Alteracao em index.html, vite.config.ts, package.json ou tsconfig.json
                        ->  reinicie o `npm run tauri dev`.
  Alteracao em src-tauri/**  ->  o `tauri dev` recompila e reabre a
                                 janela sozinho. Se nao recompilar,
                                 encerre e start de novo.
  Alteracao em src-tauri/tauri.conf.json ou src-tauri/Cargo.toml
                        ->  reinicie o `npm run tauri dev`.

------------------------------
  src/                CODIGO DA INTERFACE. Tudo o que o React desenha:
                      componentes, telas, estilos, traducoes e imagens.
                      E a pasta que voce edita 90% das vezes.
                      (nao confunda com src-tauri/)

  src-tauri/           O APLICATIVO NATIVO e o BACKEND. Aqui esta o
                      codigo Rust (src-tauri/src/), a configuracao da

     mudar de identidade. O "version" pode mudar de verdade (e deve

COMO AS REFERENCIAS FUNCIONAM
-----------------------------
  - Um SVG dentro de src/ e importado pelo codigo (import ... from
    "...svg"). O Vite transforma em URL e o copia para dist/assets/ com um
    nome com hash. Se o import estiver errado, o build falha com
    "Could not resolve".
    EXCECAO: arquivos com menos de 4 KB sao embutes no proprio JavaScript
    como "data:image/svg+xml,...". E o caso do logo de hoje (309 bytes).
    Os desenhos dos aparelhos (9 KB a 10,6 KB) passam do limite e viram
    arquivos em dist/assets/ (por exemplo
    dist/assets/iphone-island-DxwqdITg.svg).
  - Um arquivo em public/ e acessado por URL ABSOLUTA a partir da raiz
    ("/fhzipa-inject.svg"). Ele NAO passa pelo Vite e NAO ganha hash.
  - Os PNG/ICO/ICNS do instalador sao lidos pelo empacotador do Tauri a
    partir de src-tauri/tauri.conf.json.

FORMATOS E DIMENSOES ATUAIS
---------------------------
  src/recursos/imagens/fhzipa-inject.svg  ->  SVG, 309 bytes (logo do app)
  public/fhzipa-inject.svg                ->  SVG, 309 bytes (favicon)
  desenhos dos aparelhos                  ->  SVG, entre 9 KB e 10,6 KB cada
  icones do instalador                    ->  PNG de 32x32 ate 512x512, mais
                                             .ico e .icns
  Os dois fhzipa-inject.svg sao copias com o mesmo desenho, mas em
  lugares diferentes e com papeis diferentes (veja o resumo na secao E).

ONDE ESTAO AS DEFINICOES DAS ROTAS

  Este projeto NAO usa biblioteca de rotas (nem react-router). A navegacao

                         | "certificates" | "appids" | "settings";
      const NAV_ITEMS: { id: AppView; icon: IconType; labelKey: string }[] = [

        ...
      ];
      <button onClick={() => setView(item.id)} ...>

      const headerCopy = { overview: {...}, store: {...}, ... }[view];

COMO LOCALIZAR O DESTINO DE CADA ITEM DO MENU
---------------------------------------------
  1. Abra src/componentes/barra-lateral.tsx e ache o array NAV_ITEMS.
     Cada item tem: id (o destino), icon (o icone) e labelKey (a chave do
     texto no arquivo de idioma).
  2. O id corresponde a um dos valores do type AppView.
  3. Em src/app-principal.tsx, procure por {view === "<id>" } para achar o conteudo
     que aparece naquela tela.
  4. O texto do botao esta em src/idiomas/pt_br.json, no bloco "nav".

DIFERENCA ENTRE LINK INTERNO E EXTERNO NESTE PROJETO
-----------------------------------------------------
  INTERNO  = trocar o valor do estado `view` (setView("store")).
             Nao existe URL, Nao existe_history, o botao do navegador nao
             navega. Nao existe ancora <a href="#...">.
  EXTERNO  = openUrl(url) do @tauri-apps/plugin-opener.
             Sempre com openUrl, nunca com <a href>, porque o Tauri
             intercepta a navegacao do webview.
             As URLs saem de src/configuracoes/links.ts ou vem do backend
             (item.pageUrl da loja).

    TRANSLATE_URL, entao mexer nele arrasta os outros.
  - Nao ha URL publica do aplicativo: ele e desktop e usa a secao I para
    links de configuracao. Nenhuma rota da loja e publica.
  - Os destinos da loja (item.pageUrl) vem do catalogo remoto. Se voce
    trocar a fonte, a URL muda junto.

    npm run build
    npm run preview
  e abrir http://localhost:4173 no navegador.
  Lembre que no navegador a interface nao tem acesso ao backend Tauri
  (as chamadas invoke falham), entao da para conferir aparencia, textos e
  layout, mas nao as funcoes de dispositivo e conta.
  Para o funcionamento completo, use `npm run tauri dev`.

PROCEDIMENTO DE PUBLICACAO (o que ja existe no repositorio)
------------------------------------------------------------
  A publicacao e feita pelo GitHub Actions, arquivo
  .github/workflows/build.yml. Ele:
    - roda em push, pull_request, workflow_dispatch e release publicada
    - monta uma matriz de alvos: Windows, macOS (universal) e Linux
      (deb, rpm, AppImage, incluindo ARM)
    - instala o Rust e as dependencias de cada sistema
    - compila com tauri-action, usando src-tauri/ci.conf.json nas execucoes
      que nao sao release
    - ao publicar uma release, assina, notariza o .dmg no macOS e cria o
      arquivo latest.json de atualizacao
    - sobe os artefatos (.exe, .dmg, .deb, .rpm, .AppImage) e marca a
      release como "latest"
  O instalador do Windows (NSIS) sai em
  src-tauri/target/release/bundle/nsis/.
  Para publicar de verdade: crie uma release no GitHub a partir de uma tag
  e deixe o workflow rodar. Nao existe script local de publicacao.
  (Nao faca isso sem querer: a tarefa de organizacao NAO publica nada.)

  EXISTE TAMBEM UM INSTALADOR PROPRIO, COM A IDENTIDADE VISUAL DA MARCA
  Ele fica no projeto vizinho "instalador fhzipa" e e uma aplicacao WPF
  (.NET 10) que carrega este executavel como recurso e faz a instalacao
  de verdade (copia o executavel, cria os atalhos, registra o
  desinstalador e preserva os dados do usuario).
      ..\instalador fhzipa\GUIA-DO-INSTALADOR.txt
      ..\instalador fhzipa\DOCUMENTACAO-TECNICA-DO-INSTALADOR.md
  Para gerar o executavel que ele embute, faca `npm run tauri build`
  NESTE projeto e depois rode scripts\build.ps1 no projeto do instalador.
  Os dois caminhos de instalacao coexistem: o NSIS continua sendo o que o
  GitHub Actions publica, e o instalador proprio e a distribuicao com a
  identidade da marca. O caminho de atualizacao automatica (latest.json)
  continua apontando para o instalador NSIS.

  O CI instala as dependencias com `npm ci` (o mesmo package-lock.json do
  repositorio) e roda os scripts de CI com `node` em Node 20.

AMBIENTE NIX (opcional, so para quem desenvolve em Linux)
---------------------------------------------------------
  O repositorio tambem traz flake.nix / shell.nix / default.nix para
  quem usa Nix. O frontend e compilado com npm (buildNpmPackage, usando o
  package-lock.json) e o backend com cargo, como no build normal.
  Requisitos: Nix com flakes habilitado.
  Para testar:
      nix build                 # gera o pacote do aplicativo
      nix develop               # abre um shell com as dependencias
      nix fmt                   # formata os arquivos .nix
  ATENCAO: o flake foi revisado estaticamente, mas nao pode ser
  EXECUTADO no Windows (o Nix precisa de Linux/WSL). A validacao de
  verdade precisa ser feita em uma maquina Linux.

K. PROBLEMAS COMUNS
================================================================================

IMAGEM QUE NAO APARECE
-----------------------
  1. A imagem esta no lugar certo?
       - logo do menu  -> src/recursos/imagens/fhzipa-inject.svg
       - favicon       -> public/fhzipa-inject.svg
       - aparelhos     -> src/recursos/imagens/dispositivos/
  2. O import aponta para o caminho certo? (Ctrl+Shift+F pelo nome do
     arquivo). O Vite falha o build com "Could not resolve ..." se o
     caminho estiver errado.
  3. Ela esta sendo usada? Os desenhos dos aparelhos so aparecem quando ha
     um aparelho selecionado (src/componentes/render-aparelho.tsx e
     src/utilitarios/modelos-dispositivo.ts).
  4. Faltou reiniciar o `npm run tauri dev` depois de criar um arquivo
     novo? O Vite as vezes nao enxerga arquivo recem-criado.
  5. No build de producao, o SVG e renomeado com hash (por exemplo
     iphone-se-fhAaa5BN.svg). Isso e normal e nao e erro.

LOGO DISTORCIDO
---------------
  1. O SVG novo tem outra proporcao (por exemplo, um logo quadrado no
     lugar de um retangular). A regra .brand-logo em
     src/componentes/barra-lateral.css tem width/height fixos.
  2. Se o SVG tiver width/height internos, eles mandam na proporcao e o CSS
     distorce. Apague o width/height do <svg> e deixe o CSS controlar.
  3. Para o favicon, o ideal e um SVG quadrado.

LINK QUEBRADO
-------------
  1. Link externo: confira se a URL existe e se o `openUrl` esta sendo
     chamado (o `openUrl` do plugin opener e o que abre fora do app).
  2. Link de projeto: o destino vem de src/configuracoes/links.ts. Se voce
     criou um `.env`, ele tem prioridade sobre o padrao do arquivo.
  3. Link da loja: vem de item.pageUrl (dado pelo catalogo remoto). A
     pagina pode ter sumido; nao e bug do aplicativo.

PAGINA NAO ENCONTRADA (tela em branco ou vazia)
-------------------------------------------------
  Este projeto nao tem rotas nem paginas de erro 404. Se uma tela ficou
  vazia:
  1. Confirme o `view` atual: em src/app-principal.tsx o conteudo so aparece dentro
     de {view === "<id>" && ( ... )}. O id precisa bater com o type
     AppView de src/componentes/barra-lateral.tsx.
  2. A tela pode ter quebrado por um erro de dado vindo do Rust (por
     exemplo o catalogo). Olhe o terminal do `npm run tauri dev` e o
     painel de logs (Ajustes > Verificar registros).

ALTERACAO QUE NAO APARECE
--------------------------
  1. Salvou o arquivo? (Ctrl+S; o VS Code mostra um circulo na aba se
     houver alteracao nao salva.)
  2. O hot reload pegou? O Vite recarrega sozinho; se nao, Ctrl+R na
     janela do aplicativo.
  3. Alterou CSS? some com o cache do navegador (Ctrl+Shift+R) e
     reinicie o `npm run tauri dev`.
  4. Alterou um arquivo de traducao? Precisa reiniciar o Vite: o glob
     `import.meta.glob("../idiomas/*.json")` so e lido na partida.
  5. Alterou Rust? O `tauri dev` recompila, mas a recompilacao pode
     demorar. Se nao recompilar, encerre e start de novo.
  6. Alterou index.html, vite.config.ts ou package.json? Reinicie o
     processo inteiro.

ERRO DE IMPORTACAO / "Could not resolve"
-----------------------------------------
  1. O caminho do import esta errado depois de uma movimentacao de arquivo.
     Compare com o caminho real em disco (Ctrl+P no VS Code).
  2. Extensao esquecida: o import de CSS precisa ser `import "./x.css";`
     e o de imagem precisa existir de verdade.
  3. `npm run build` roda o tsc primeiro: se ele acusar modulo nao
     encontrado, o problema e um import. Rode `npx tsc --noEmit` para ver
     a lista completa dos erros de uma vez.
  4. Pasta nova sem arquivo: o Vite resolve por caminho exato, nao por
     convencao de pasta.

ERRO AO INSTALAR DEPENDENCIAS
------------------------------
  1. Use npm (o lock e package-lock.json). `npm ci` reinstala do zero
     respeitando o lock.
  2. "peer dependency" ou versao conflitante: apague node_modules e rode
     `npm install` de novo.
  3. "EACCES" ou erro de permissao no Windows: abra o terminal como
     Administrador ou desative o antivirus momentaneamente.
  4. Se aparecer algo relacionado a "bun" ou "pnpm", e porque algum
     comando ou documentacao ainda usa outro gerenciador. Use npm.
  5. "npm ci" falhou complaining que o package.json e o package-lock.json
     nao batem: rode `npm install` uma vez (ele atualiza o lock), confira
     a mudanca com `git diff package-lock.json` e so entao volte a usar
     `npm ci`. Nao apague o package-lock.json para sair do problema.

ERRO AO INICIAR
---------------
  1. "Port 1420 is already in use": ja existe um Vite rodando. Feche o
     processo antigo (o terminal onde ele started) ou rode
     `npx kill-port 1420`.
  2. "linker `link.exe` not found": falta o Visual Studio Build Tools com
     a carga "Desenvolvimento para Desktop com C++". Instale e reinicie
     o terminal.
  3. "failed to run custom build command" / erro do tsc: o problema e de
     codigo, rode `npm run build` para ver a mensagem exata.
  4. Tela branca no navegador: normal. O aplicativo precisa do runtime
     Tauri. Use `npm run tauri dev`.
  5. "WebView2 not installed": instale o WebView2 Runtime.

DIFERENCA ENTRE FUNCIONAMENTO LOCAL E PUBLICACAO
-------------------------------------------------
  - Em desenvolvimento (`npm run tauri dev`) o frontend vem do servidor
    Vite (http://localhost:1420) e voce ve as alteracoes na hora.
  - Na versao de producao (`npm run tauri build`, ou o instalador pronto)
    o frontend vem EMBUTIDO no executavel (a pasta dist/ e congelada
    durante a compilacao). Se voce mexer no frontend e nao recompilar o
    Rust, a janela continua mostrando a versao antiga.
  - A versao local mostra o endereco do servidor na barra de status; na
    publica mostra "app://localhost".
  - O instalador (.exe) e assinado e.tar com as configuracoes de
    publicacao do .github/workflows/build.yml; localmente nao ha assinatura.
  - Antes de publicar de verdade, rode `npm run build` e `npm run preview`
    para conferir a versao de producao.

================================================================================
L. COMO EDITAR COM SEGURANCA
================================================================================

COMO SALVAR ARQUIVOS
--------------------
  Ctrl+S. O VS Code salva automaticamente se voce tiver ativado
  "files.autoSave". O indicador da aba (circulo) mostra arquivo nao salvo.
  Formate SEMPRE com o mesmo estilo do arquivo: 2 espacos, aspas duplas,
  ponto e virgula, LF ou CRLF conforme o arquivo original. Evite o
  "formatar documento" automatico em arquivo grande: o VS Code pode
  reescrever o arquivo inteiro e sujar o diff.

COMO PESQUISAR UM TEXTO NO PROJETO
-----------------------------------
  Ctrl+Shift+F (Search across files).
  Filtros uteis:
    files to include:  src/          (ou src/paginas/, src/idiomas/)
    files to exclude:  dist, node_modules, src-tauri/target
    regex:             marque a opcao .* na busca
  Para procurar apenas um tipo de arquivo, use a extensao no filtro
  (ex.: include "*.tsx").

COMO LOCALIZAR UM ARQUIVO
-------------------------
  Ctrl+P (Quick Open) e digite o nome do arquivo. Funciona sem precisar
  lembrar a pasta.
  Ctrl+G e Ctrl+P tambem funcionam para pular para um numero de linha ou
  para um simbolo (funcao, classe, variavel).

COMO REVISAR O QUE FOI MODIFICADO
---------------------------------
  Se voce usa Git (o projeto tem .git):
    No VS Code, aba "Source Control" (Ctrl+Shift+G) mostra a lista de
    arquivos modificados. Clique no arquivo para ver o diff, com as linhas
    antigas em vermelho e as novas em verde.
    No terminal:
        git status              lista o que mudou
        git diff                mostra as mudancas nao confirmadas
        git diff --stat         so o resumo por arquivo
  O diff em vermelho/verde e o jeito mais seguro de conferir que voce so
  trocou o que queria. Conferir o diff ANTES de confirmar (commit) e
  obrigatorio.

COMO VOLTAR UMA ALTERACAO PROPRIA SEM PERDER OUTRAS MUDANCAS
-------------------------------------------------------------
  Do jeito mais seguro (descarta so a mudanca de um arquivo):
    1. Source Control > clique no arquivo > gear > "Discard Changes"
    2. O VS Code pergunta de confirmacao; confirme.
  No terminal, o equivalente:
    git restore -- "caminho/do/arquivo"     (descarta o arquivo inteiro)
    git restore -p -- "caminho/do/arquivo"  (descarta pedaco a pedaco,
                                              com o que voce escolher)
  CUIDADO: "Discard Changes" apaga TUDO que voce fez no arquivo, nao so a
  ultima edicao. Se o arquivo tem varias mudancas suas, prefira
  `git restore -p`.
  NUNCA use `git reset --hard`, `git checkout .` ou `git clean -fd` sem
  certeza: isso apaga trabalho que nao esta no commit.

ARQUIVOS QUE NAO DEVEM SER EDITADOS DIRETAMENTE
------------------------------------------------
  dist/                      - gerado por `npm run build`
  node_modules/              - gerado por `npm install`
  src-tauri/target/          - gerado pelo cargo
  src-tauri/gen/schemas/     - gerado pelo Tauri
  package-lock.json          - gerado pelo npm (mude o package.json)
  src-tauri/Cargo.lock       - gerado pelo cargo
  src/vite-env.d.ts          - e um arquivo de tipos; so mude se souber o
                               que esta fazendo
  src/idiomas/*.json         - edite o que voce quiser, mas MANTENHA as
                               chaves identicas entre os idiomas (a chave
                               e o que o codigo procura)

CUIDADOS COM ARQUIVOS DE AMBIENTE
---------------------------------
  - O arquivo `.env` fica na raiz e NAO deve ser commitado. Confirme que
    ele esta no .gitignore antes de dar `git add .`.
  - Nao coloque senha, token ou chave de API em variavel VITE_*: o
    prefixo VITE_ faz o valor ser embutido no JavaScript do aplicativo e
    ficar visivel para qualquer pessoa.
  - O arquivo `.env` e lido so na partida do Vite: mudei-lo, reinicie.
  - Se o .env tiver valor errado, o botao de GitHub, o link de issues, o
    Discord, os sponsors ou o link de traducao vao apontar para o lugar
    errado. Confira em src/configuracoes/links.ts.
