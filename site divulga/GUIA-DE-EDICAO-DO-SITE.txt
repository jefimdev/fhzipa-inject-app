1. O QUE ESTE SITE É
===============================================================================

Uma página única (index.html) que apresenta o aplicativo, mostra capturas
reais, explica os requisitos e entrega o instalador por link direto.

Tecnologia: HTML5 + CSS3 + JavaScript puro (sem framework, sem biblioteca,
sem etapa de compilação). Escolha feita porque:

  - o site é uma página só, com um menu, uma galeria, um FAQ e um bloco de
    download;
  - não existe dependência para instalar, o que mantém o site separado do
    aplicativo (que usa React + Tauri) e impede mistura de dependências;
  - o resultado pode ser publicado em qualquer hospedagem de arquivos
    estáticos, sem servidor, sem banco de dados e sem backend;
  - o carregamento é imediato: uma folha de estilo e um script pequeno.

O site NÃO usa analytics, rastreadores, pixel de publicidade, cookies não
essenciais nem formulários. Não há backend nem endpoint de download: o
arquivo é servido direto do servidor de arquivos estáticos.

3. REQUISITOS
===============================================================================

Para editar o conteudo (só texto, cores, links):
  - um editor de texto. Nenhuma instalacao necessaria.

Para executar localmente:
  - Python 3 (ja vem com o Windows 11 e com o Windows 10 atual) ou Node.js.
  - Alternativa: abrir o index.html direto no navegador com duplo clique

    pacote global do Playwright MCP:
      CAMINHO_PLAYWRIGHT\\node_modules\\@playwright\\mcp\\node_modules\\playwright-core
    Ajuste a variavel CAMINHO_PLAYWRIGHT ou instale localmente com:
      npm i -D playwright-core
    E o navegador precisa estar em:
      %LOCALAPPDATA%\\ms-playwright\\chromium-1248\\chrome-win64\\chrome.exe
    (ajuste a variavel NAVEGADOR se a versao do Chromium for outra).

Para preparar o download:
  - Windows com PowerShell 5.1 ou superior. Nao precisa de .NET SDK.

Nao e preciso de Node, Rust, Visual Studio ou Android Studio para publicar o
site. Esses itens sao do desenvolvimento do APLICATIVO, nao do site.

11. COMO ATUALIZAR A VERSAO E A URL DO INSTALADOR
===============================================================================

A fonte unica de verdade dos dados do pacote e o bloco JSON no inicio do
index.html:

  <script type="application/json" id="dados-download">
  {
    "arquivo": "FHZIPA_INJECT_Setup.exe",
    "url": "downloads/FHZIPA_INJECT_Setup.exe",
    "versao": "1.0.0",
    "plataforma": "Windows 10 ou 11",
    "arquitetura": "x64 (64 bits)",
    "bytes": 70824110,
    "sha256": "743e40a4...",
    "data": "2026-10-21",
    "assinado": false
  }
  </script>

O JavaScript da pagina le esse bloco e preenche a versao, o tamanho, a data, o
SHA-256 e o nome do arquivo em todo o site. Nao repita esses valores em
outros lugares.

ATENCAO: o bloco JSON-LD (application/ld+json), um pouco mais abaixo, tem
os mesmos dados para os buscadores. Atualize os dois no mesmo momento.

Para trocar a URL do instalador (por exemplo, se o arquivo passar a ficar em
outro endereco do servidor):
  - "url" no bloco dados-download;
  - os tres links de download do index.html (o do menu, o da primeira tela e
    o da secao de download): href="downloads/FHZIPA_INJECT_Setup.exe";
  - "downloadUrl" e "fileSize" no bloco JSON-LD.

O atributo download funciona porque o arquivo esta no mesmo dominio. Se o
arquivo passar a ficar em outro dominio, o atributo download e ignorado
pelos navegadores e o arquivo abrira numa aba nova em vez de baixar.

12. COMO ATUALIZAR O TAMANHO E O SHA-256
===============================================================================

Rode o script de preparacao. Ele copia o instalador aprovado, compara o
SHA-256 com o valor esperado e so prossegue se bater:

  powershell -ExecutionPolicy Bypass -File scripts\preparar-distribuicao.ps1

Se o artefato novo for legitimo, atualize o valor esperado no proprio script
(parametro -EsperadoSha256) e rode de novo. Depois atualize no index.html:

  "bytes"  -> o numero exato de bytes (o script imprime);
  "sha256" -> o resumo que o script imprime;
  "data"   -> a data da versao, no formato AAAA-MM-DD.

O script tambem grava downloads\SHA256SUMS.txt, que e o arquivo de
referencia para quem for conferir o download.

Se o SHA-256 nao bater, o script sai com codigo 2 e NAO publica. Nao copie o
arquivo para a pasta downloads/ na mao nesse caso.

13. COMO VERIFICAR O DOWNLOAD
===============================================================================

Antes de publicar:

  1) Suba o site com o servidor local e baixe pelo botao.
  2) Confira o arquivo baixado:

       Get-FileHash .\FHZIPA_INJECT_Setup.exe -Algorithm SHA256

     O valor tem de ser igual ao do bloco dados-download e ao do
     SHA256SUMS.txt.

  3) Confira os cabecalhos HTTP do servidor (o navegador precisa receber
     o arquivo como binario, nunca uma pagina de login ou de erro):

       curl.exe -sI http://127.0.0.1:8899/downloads/FHZIPA_INJECT_Setup.exe

     O esperado e:
       HTTP/1.1 200 OK
       Content-Type: application/octet-stream   (ou application/x-msdownload)
       Content-Length: 70824110

  4) Teste sem sessao autenticada (janela anonima do navegador) para
     garantir que nao existe dependencia do login do GitHub.

  5) Confirme que nenhum token aparece na pagina:

       curl.exe -s http://127.0.0.1:8899/ | findstr /I "ghp_ gho_ ghs_ Authorization"

     Nao deve aparecer nada.

14. COMO PUBLICAR
===============================================================================

O repositorio do codigo-fonte e privado e NAO deve virar publico. O site e
publicado em uma hospedagem de arquivos estaticos, separada do repositorio.

Sequencia sugerida:

  1) Decidir e contratar (ou nao) a hospedagem. Verifique se ela aceita
     um arquivo de 67 MB e qual o limite de armazenamento.
  2) Esvaziar downloads\ antes do upload se a hospedagem tiver limite de
     tamanho, e enviar o .exe por um canal proprio (por exemplo, um
     bucket de objeto com link publico de leitura).
  3) Enviar o restante do site.
  4) Configurar HTTPS (a hospedagem normalmente oferece certificado
     automatico). Um site de download sem HTTPS derruba a confianca do
     visitante e o navegador avisa.
  5) Trocar o robots.txt de "Disallow: /" para "Allow: /".
  6) Trocar SEU-DOMINIO pelo dominio real em sitemap.xml.
  7) Acrescentar no index.html a URL canonica e transformar a URL da imagem
     social em absoluto:
       <link rel="canonical" href="https://SEU-DOMINIO/">
       <meta property="og:image" content="https://SEU-DOMINIO/img/social-compartilhamento.png">
     (as redes sociais nao leem URLs relativas para imagem de
     compartilhamento)
  8) Registrar o dominio em Google Search Console e enviar o sitemap.xml.
  9) Testar tudo de novo no endereco publico, com o endereco real.

O checklist completo esta em CHECKLIST-DE-PUBLICACAO-DO-SITE.txt.

  git status                      # o que mudou
  git diff                        # o que mudou, linha a linha
  git restore "site divulga"      # volta tudo ao ultimo commit
  git restore "site divulga/css/estilo.css"   # volta so um arquivo

  git revert <hash-do-commit>     # cria um commit que desfaz

  e reenvie os arquivos ao servidor de hospedagem.

Se a hosting usa FTP ou upload manual, guarde uma copia da versao publicada
antes de enviar a nova (por exemplo, em Backups-FHZIPA-INJECT).

16. PROBLEMAS COMUNS
===============================================================================

"Na pagina aparece 'Verificando a disponibilidade do instalador' e nunca
  troca."  Voce abriu o arquivo direto (file://). O navegador bloqueia a
  consulta HEAD. Use o servidor local.

"O botao de download baixa um arquivo de 0 byte ou uma pagina de login."
  O arquivo nao foi enviado para downloads\ no servidor. Confira o
  Content-Length com o curl.

"A imagem de compartilhamento nao aparece no Facebook/LinkedIn."
  A URL do og:image precisa ser absoluta (https://SEU-DOMINIO/...), e o
  arquivo precisa estar acessivel sem sessao.

"O Google nao indexa o site."
  O robots.txt ainda esta com "Disallow: /" e o sitemap.xml ainda tem
  SEU-DOMINIO. Troque os dois.

"A galeria ficou com as imagens cortadas."
  Nao use object-fit: cover nas capturas. O css atual mostra as imagens
  inteiras, sem corte.

"O site ficou largo demais no celular (rolagem na horizontal)."
  Nao use minmax com valor fixo nas grades. O padrao do projeto e
  minmax(min(300px, 100%), 1fr).
